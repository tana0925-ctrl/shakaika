# 社会科同好会 成長の道しるべ（学びのコンパス）

## Project Overview
- **Name**: 社会科同好会 成長の道しるべ
- **Goal**: 会員が自分の現在地と次のステップを選択・記録でき、管理者が全会員の状況を一覧で把握できるWebアプリ
- **Features**: 
  - 会員登録・ログイン認証
  - 5つの成長視点 x 4段階ステップの対話型ルーブリック
  - 各セルをクリックして「今の自分」を選択・メモ付きで保存
  - 管理者ダッシュボード（全会員の選択状況を一覧表示）
  - CSV(Excel対応)エクスポート機能
  - A4横印刷対応

## URLs
- **ログインページ**: `/login`
- **マイページ（会員用）**: `/mypage`
- **管理者ダッシュボード**: `/admin`
- **DB初期化**: `/api/init`（初回アクセス時に1度実行）

## API Endpoints
| Method | Path | 説明 |
|--------|------|------|
| GET | `/api/init` | DB初期化＆管理者アカウント作成 |
| POST | `/api/auth/register` | 会員登録 |
| POST | `/api/auth/login` | ログイン |
| GET | `/api/auth/me` | 現在のユーザー情報取得 |
| GET | `/api/selections` | 自分の選択状況取得 |
| POST | `/api/selections` | 選択を保存/更新 |
| DELETE | `/api/selections/:viewpoint` | 選択を削除 |
| GET | `/api/admin/members` | 全会員一覧（管理者のみ） |
| PUT | `/api/admin/members/:id/role` | 役割変更（管理者のみ） |
| DELETE | `/api/admin/members/:id` | 会員削除（管理者のみ） |
| GET | `/api/admin/export` | CSV エクスポート（管理者のみ） |

## Default Admin Account
- **Email**: admin@example.com
- **Password**: admin123

## Data Architecture
- **Database**: Cloudflare D1 (SQLite)
- **Tables**: 
  - `users` - 会員情報（名前、メール、パスワードハッシュ、役割）
  - `selections` - 各会員の選択記録（視点、ステップ、メモ）
- **Authentication**: SHA-256ハッシュ + Bearer Token

## User Guide
1. `/api/init` にアクセスしてデータベースを初期化
2. `/login` で新規登録またはログイン
3. マイページでルーブリック表のセルをクリックして「今の自分」を選択
4. メモを追加して「保存する」ボタンを押す
5. 管理者は `/admin` で全会員の選択状況を確認、CSVダウンロード可能

## みんなの気づき（2026-10-23 追加）
- 回答フォーム（会員・ゲスト共通）の最後に、任意の同意欄「名前なしで紹介してもよい／名前ありで紹介してもよい」が自動で付く（質問ではないのでCSV・質問数には入らない）。同意は share_consents（anon / named / none）。この機能より前の回答には行が無く、紹介の対象外。
- 管理者：イベント管理 → 各回の「みんなの気づき」タブで、同意した人の文章回答だけを一覧。文面を直して「採用」／取り消し。採用文は shared_insights に別保存（元の回答は書き換えない）。
- 表示：会員が受付QRで出席した画面（前回の学びカードの下）に「前回のみんなの気づき」、マイページ → /mypage/insights に研修会ごとの一覧。どちらもログインした会員のみ。名前あり同意は名前だけ（学校名なし）、名前なし同意は名前を出さない。表示のたびに今の同意を確認する。
- ゲストの受付画面には出さない（ログイン不要の画面のため、外部の人に見えてしまうおそれがある）。
- migration 0007（D1に適用済み）。
- 対象にする回の設定（2026-10-24 追加・管理者のみ）：イベント作成・編集（✏️）の「みんなの気づきの対象にする」（events.insights_enabled、既定値1＝ON、migration 0012・D1に適用済み）。OFFの回は、回答フォームに同意欄を出さない（送られても保存しない）／管理画面の「みんなの気づき」タブは「対象外の回です」と表示し採用もできない／受付QRの「前回のみんなの気づき」（OFFの回は飛ばして、その前のONの回を探す）とマイページ一覧に出さない／マイページの同意の変更欄も出さない。途中でOFFにしても share_consents・shared_insights は消さず、ONに戻せば再表示。イベント一覧に「気づき対象外」の小さな印。

## 分析ダッシュボード・視点の読みかえ表（2026-10 追加・管理者のみ）
- 管理画面 →「分析」（/admin/analytics）：年度全体・回ごとの参加人数／回答人数／回答率、成長の視点（「選んだ人の割合」と「全選択に占める割合」を分母つきで区別）、回ごとの比較（割合）、前回の学びカードのボタン集計、自由記述の一覧と語の頻度。AIは使わない。
- 「AIに貼る用にコピー」：名前などを伏せた文章（「回答の傾向」と「運営への提案」を分けて書く指示つき）を作り、外部AIに貼る。
- 「読みかえ表」（/admin/viewpoints）：表記ゆれの選択肢を共通の視点名にまとめる対応表（viewpoint_aliases、migration 0008）。元の回答は書き換えない。コードは src/growth_common.ts・src/growth_analytics.ts。
- 初期値：「カフート」は先生の判断で「その他」にまとめている（読みかえ表で変更できる）。

## 学びの記録（個人ポートフォリオ）（2026-10 追加）
- マイページ →「わたしの学びの記録」（/mypage/portfolio）、管理者は会員一覧の芽のボタン（/admin/portfolio?uid=）。本人と管理者のみ。
- 参加した研修会、選んだ視点（読みかえ表でまとめる）・理由・試してみたいこと、前回の学びカードを時系列で。視点の回数と回ごとの変化、道しるべ（STEP）とのつながり、本人の記述からテンプレートで作る「次の目標を考えるための問い」。点数・順位・評価は出さない。コードは src/growth_portfolio.ts。

## 年度末の成長レポート・印象に残った言葉（2026-10 追加）
- 学びの記録 →「年度末の成長レポート」（/mypage/report、管理者は /admin/report?uid=）。参加履歴・視点の移り変わり・印象に残った言葉・前回の学びカード・今年度の目標／振り返り・来年度に向けた問い。印刷用レイアウトで、ブラウザの印刷から「PDFに保存」。AIによる評価文は入れない。
- 印象に残った言葉：学びの記録で自分の記述の☆を押して残す（kept_words、migration 0009）。元の回答は書き換えない。

## 重複のまとめ（2026-10 追加・管理者のみ）
- 管理画面 →「重複のまとめ」（/admin/duplicates）。同姓同名・表記ゆれの会員どうし、会員と同名のゲストを一覧。自動統合はしない。見比べて「同じ人だと確認しました」にチェックしたときだけ統合。
- ゲスト→会員：回答を会員の回答として付け替え（ゲストの元の行は統合の記録に保存）。会員どうし：重ならない記録だけ残す側へ付け替え、重なる記録と元のアカウントは残す。
- すべて merge_logs に記録し、「統合の記録」から元に戻せる。「別人として記録」で候補から外せる（duplicate_dismissals）。migration 0010。コードは src/growth_duplicates.ts。

## 新着の振り返り・スマホへの通知（2026-10 追加・管理者のみ）
- 管理画面 →「新着」（/admin/news）。研修会後のアンケート（会員・ゲスト）、前回の学びカード（ボタン／一言）、マイページの今年度の振り返りが送られると、裏の処理（waitUntil）で reflection_feed に入る。送信そのものは待たせず、通知の失敗は無視（送信は成立）。同じ内容の再送は新着にしない。
- 受け取る対象は事務局ごとに3択：全員（ゲストもふくむ・初期値）／選択した人（会員一覧の🔔・会員詳細・新着画面の名前検索で選ぶ。admin_watch_members）／受け取らない（新着も通知もなし）。グループは使わない。
- 既読は事務局ごと（feed_reads）。「すべて既読」は時刻を1つ記録するだけ。新着は60日・最大100件、件数は200件まで数える。
- スマホ通知（Web Push・無料）：「この端末で通知を受け取る」。通知の文は「新しい振り返りが〇件あります」だけ（名前・中身なし）。タップで /admin/news。404/410 の端末は自動で削除。iPhone はホーム画面に追加して開いたときだけ。
- タイミング：1日1回まとめて（夜20時ごろ・初期値）／その都度（10分以内に続いたらまとめる）。まとめ送信は /api/notify/tick を Cloudflare Worker「shakaika-notify-cron」（tools/notify-cron-worker.js、Cron */10 * * * *）が呼ぶ。管理画面を開いたときにも裏で呼ぶ。
- 鍵：Pages のシークレット VAPID_PUBLIC_KEY（公開鍵）と VAPID_PRIVATE_KEY（秘密鍵。コード・リポジトリには入れない）。ダッシュボード → shakaika → 設定 → 変数とシークレット（本番）。鍵を作り直したら、全員「この端末で通知を受け取る」を押し直す。
- migration 0011（D1に適用済み）。コードは src/growth_notify.ts。

## 個人まとめシート（2026-10 追加・管理者のみ）
- 会員1人分を A4縦1枚にまとめた印刷用シート（/admin/sheet?uid=）。画面でもそのまま見られ、「印刷・PDFで保存」で印刷／PDF。入りきらないときは文字を小さくし、古い回から省略して必ず1枚に収める（2ページ目に流れない）。
- 載せる内容：名前・学校・地区・グループ・校種／参加回数・対象回数・参加率と対象回の一覧（○出席・－欠席）／今年度の目標・振り返り／成長の道しるべ（STEPとメモ）／選んだ成長の視点の回数（読みかえ表でまとめる）／振り返りのあゆみ（選んだ理由・試してみたいこと・前回の学びカード）／☆をつけた印象に残った言葉。点数・順位・評価は出さない。
- 対象回の決め方（会名から判定）：全体向けの会は全員。「小学校部会」「中学校部会」「小中合同」はその校種、「グループ」「授業力アップ」は会名のグループの会員。まだ開かれていない回・出席者0の回は数えない。本人が出席した回は必ず含む。
- 開き方：会員一覧の詳細（名前クリック）・学びの記録（管理者として閲覧）の「1枚シート」。まとめ印刷は会員一覧の「選んだ人の1枚シート」「表示中の全員の1枚シート」、グループ別の各グループの「1枚シートをまとめて印刷」（グループ別画面と同じ並び、1人1ページ）。
- グループ名は全角/半角・前後空白をそろえて照合（「Ｇ」と「G」は同じグループ。グループ別画面の分け方も同じ。元のデータは書き換えない）。
- API：GET /api/admin/sheets?uids=（1回10人まで。画面側で分けて読む）、GET /api/admin/sheet-ids?group=｜unset=1。会員本人の画面にはボタンを出さず、APIは管理者以外403。新しいテーブルなし。コードは src/growth_sheet.ts。
- グループ別画面の印刷ボタン整理：上部の「このグループを印刷」は各グループの「印刷」と同じ動き（画面の一覧をそのまま印刷）だったため削除。各グループの「印刷」は「一覧を印刷」に名前を変えて残す（伴走メモ・回答全文を含む一覧形式で、1枚シートとは役目が違うため）。

## アプリとしてインストール（ホーム画面に追加）（2026-10 追加・会員も管理者も）
- 全ページで /manifest.webmanifest を読み込む（src/index.tsx の commonHead）。アプリ名「学びの道しるべ」（name・short_name とも）。アイコンは public/static/icons（オレンジに「社」）。
- 開くと start_url「/」→ ログイン画面 → ログイン済みなら会員はマイページ、管理者は管理画面へ自動で進む（iPhoneのホーム画面アプリはSafariとログインが別なので、最初に一度ログイン）。
- 通知・新着の機能とボタンは引き続き管理者だけ（/admin/news と /api/notify/*）。/admin.webmanifest は以前の名前として同じ内容を返す。
- ブラウザの自動のインストール案内は出さない（beforeinstallprompt を止めて保存。src/app_install.ts）。マイページと管理画面の上に小さな「📱 ホーム画面に追加」カード（×で閉じるとその端末では出さない・ホーム画面から開いているときや追加済みは出さない）。Android/Chromeはボタンで本来の追加画面、iPhoneは絵入りの手順。受付QRの画面には出さない。いつでも /app-install（プロフィール設定・新着の設定にリンク）から追加できる。
- 管理画面のページ（/admin と /admin/*）はサーバ側で管理者かを確かめてから返す：ログイン時に HttpOnly クッキー sk_sess を渡し、未ログイン→ログイン画面、一般会員→マイページへ戻す。以前からログインしている端末は、ログイン画面を一度通るとクッキーが付く（/api/auth/session-cookie）。ログアウトでクッキーも消す。
- 管理画面のページと /api/* の返事は Cache-Control: no-store。Service Worker（/sw.js）は通知の表示だけで、ページやAPIの返事を保存（キャッシュ）しない。
- 共通の入口「/」：クッキーで管理者→/admin、会員→/mypage、未ログイン→/login。
